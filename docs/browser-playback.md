# Browser endpoint playback

`BrowserAudioSink` connects authenticated endpoint PCM to an explicitly supplied `AudioContext`. The application resumes the context through an appropriate user gesture, obtains a signed playback lease through the E2EE control decoder, and supplies the same disciplined time source used for the timeline. The sink never changes a system volume slider, selects a song or asserts that the browser's current output is an external speaker.

Scheduling uses the audio context clock, validates PCM shape/rate, deinterleaves only the scheduled range and rejects overlapping output. Rates must match the context; resampling is a separate adapter. The queue has a default one-second horizon, a five-second configuration ceiling and an independent sample-memory ceiling. Returned alignment is always `timeline-only`.

The gain node applies the minimum of signed operating limits and user consent, schedules the lease fade, and stops the source at the earlier content/authority/queue boundary. Renewing authority does not extend an already queued clip. Call `refreshAuthority` after accepting a control, and use the sink's gain/mute/leave methods for immediate user actions. The sink clears sources on all context state transitions, explicit route invalidation and closure. Completed/discarded buffer copies are overwritten where the Web Audio API permits; this is local cleanup, not a global recall guarantee.

An audio context's clock pauses while suspended. Applications must clear the queue before explicit suspension/resumption, recheck wall-clock authority on resumption and rejoin the live timeline. The state listener also clears queues, but an automatically resumed browser can render before JavaScript receives the event; the bounded queue limits that residual exposure. A browser whose lifecycle behavior cannot satisfy the chosen operating policy must remain unsupported for unattended/public output. Native enforcement and actual browser/device lifecycle tests remain qualification gates.

Portable graph tests verify channel/offset copying, fade and stop times, no-authority silence, rate/overlap/memory bounds, lifecycle resets, mute/leave, emergency changes and plaintext buffer cleanup. These tests use a graph double and do not establish browser interoperability or acoustic timing. The API follows the standard [Web Audio interfaces](https://www.w3.org/TR/webaudio/#AudioBufferSourceNode), with the implementation restricted to broadly available buffer, gain, scheduling and state APIs.
