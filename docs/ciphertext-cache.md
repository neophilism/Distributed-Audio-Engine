# Opaque endpoint and edge cache

`EndpointCiphertextCache` stores only encrypted chunks and opaque scope/object/index, ciphertext size and retention/access metadata. Its schema has no private manifest, attachment key, filename, media type or plaintext hash. Cache possession is never recipient authorization, a playback right or acoustic evidence. The endpoint player still authenticates its private descriptor and every chunk and checks playback permission before scheduling.

The policy validates scope and exact chunk length, caps bytes/entries, applies least-recent-access eviction, purges expired entries and refuses conflicting duplicates. Rewriting the same live ciphertext cannot extend its original retention deadline. A persistent monotonic time watermark rejects a backwards clock even after cache reopening. The configured retention ceiling is 30 days; long archives need a separately assessed profile. A deployed service must apply primary/replica/back-up retention beyond this local adapter.

`CachingChunkTransport` coalesces identical in-flight ciphertext requests. A canceled subscriber gets no result, while other subscribers retain their shared fetch; the last canceled subscriber aborts and abandons it. Old operations cannot poison a fresh request. Reader authentication failure invalidates the cached chunk. A closed transport never writes a late result. None of these cache operations persist decoded PCM or distribute keys.

The portable entry point exports the policy and memory store. The Node-only `@neophilism/distributed-audio-engine/node` subpath exports `SqliteCiphertextCacheStore`, using the built-in SQLite API on the pinned Node runtime. Prepared parameters, strict tables, disabled extension loading and synchronous full-durability transactions cover eviction, inserts and watermark updates atomically. Index scans read metadata instead of copying all ciphertext. The application owns the database location, filesystem access, storage capacity and backup policy. SQLite operations are synchronous; high-volume deployments should isolate them from an audio callback and qualify workload limits.

Tests use actual file databases to verify reopening, expiry/watermark persistence, transaction rollback and absence of supplied private metadata/key/plaintext markers from the cache file. This is adapter evidence, not a deployed crash/restore or forensic deletion guarantee. Removing ciphertext rows cannot recall plaintext or keys already delivered to recipients. The built-in API is described in the [Node 24 SQLite documentation](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html).
